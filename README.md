* **REQUIREMENT:** To make the game more challenging, I implemented several of the features together to balance it out. Firstly, making the aliens speed up on a linear scale based on the number of aliens destroyed so every alien destroyed increases the difficulty. I had to ensure the starting AND max speeds were suitable so that it wouldn’t speed up to an impossible speed at the end. I also made multiple levels changing the difficulty and strategy. I increased the cooldown of bullets so you can’t just stream endless bullets and win instantly either lol.

I will go back and actually add in some better graphics for the ship and player later on, but my main goal with this project was getting used to Unity and its syntax, which I can say I absolutely did, hence the emphasis on the code rather than the graphics.

## PlayerController.cs
* **CHANGE:** Instead of simply using position.x I used a vector to input the direction horizontally. While a bit overkill given we’re just going in one direction (X axis), vectors are also how we began to represent directional data (esp multi-directional data) in the later projects so I want to keep my syntax consistent. Regardless, using Input.GetAxisRaw("Horizontal"); prevents me from having to rewrite the same x position change for the left and right arrow keys separately. In fact, this works on AWDS keys as well, which are arguably easier to press on a keyboard.
* **CHANGE:** On that note, GetAxisRaw was used to make snappier arcade-like motion. Without it, there would be acceleration so smooth starts and stops. While this has a time and a place (moreso in more realistic-physics based games), it is a bit easier for the player to instantly start and stop as traditional arcade games go.
* **CHANGE:** Recalculating the time to the next fire in the if statement every single time is highly inefficient and should be done in the code block AFTER each shot. (I have PTSD from Distributed System’s Test and Set that would inefficiently do a write every single time…)
* **REQUIREMENT:** To prevent the space ship from moving off screen if someone held the arrow key too long, I used the clamp feature to “clamp” the boundaries. I could’ve just checked coordinates too, but this neatly and more efficiently checks if pos > max, ret max & if pos < min, ret min, which basically pushes the player back to the bound if they pass it.

## Projectile.cs
* **CHANGE:** To prevent the Aliens from remaining on screen forever, we delete the Alien after a given ‘lifetime’ seconds, as we don’t want to end up wasting memory. Instead of using coordinates which can be volatile based on how large we make the playing ground, a timer will always delete the projectile after a set number of seconds regardless of changes I may make to the ground.

## Alien and AlienFleet.cs
* **CHANGE:** Since public AlienFleet fleet is already a reference to the AlienFleet component we can just call fleet.aliens.Remove(gameObject) no need for a getter.
* **CHANGE:** To ensure that we don’t accidentally have our projectile or player bounce off an enemy we should make both the alien and projectile into a trigger object not a collider. Triggers act like a laser tripwire where the projectile will pass through the alien without any unwanted physics based events, unlike a collider. (Think Super Mario collecting a coin by passing through rather than bouncing back if he hits a brick). Changed the OnCollisionEnter function to OnTriggerEnter.
* **CHANGE:** To make the dimensions automatically adapt no matter the camera angle or size of the aliens, I used Camera.main.ViewportToWorldPoint(new Vector3(0, 0, zDistance)); and Camera.main.ViewportToWorldPoint(new Vector3(1, 1, zDistance)); to get the top left and bottom right corners based on the camera not actual coordinates that can vary. (Really didn’t want to have to change my code every time I made a change to the camera or other dimensions…)
* **REQUIREMENT:** To make different level spawns (and also to make the spawning much easier to control) I created level layout array variables in alienFleet.cs where a 1 means an alien spawns, and a 0 has an empty space. So when actually spawning a level, it takes right from this array and I don’t have to worry about exactly programming the dimensions where each alien goes! One logic loop, infinite level possibilities! (Side note, this reminds me a lot of those 2d shapes we made in CS 111 lol)
* **REQUIREMENT:** To make the aliens speed up as their compatriots are destroyed, I used mathf.lerp (linear interpolation) that smoothly changes the list size by calculating an interpolated increasing scale based on the number of aliens left. (This was actually a nice application of interpolation that I learned from Numerical Methods!) At each change in the number of aliens, we scale the speed until the max speed possible is reached (we don’t want to make it too impossible lol). The linear interpolation calculates a value between 2 points (our starting and stopping speed), and as the percent of aliens remaining decreases, we will scale further up based on the magnitude calculation. Having a starting and max speed made it easy to pinpoint the exact difficulty I wanted.
* **REQUIREMENT:** To end the game when it’s impossible to win, we test to see if the bottommost alien reaches the same coordinate as the player’s ship currently is. In the same loop that tracks if each alien is touching a left/right bound, we also test if they are at the player’s coordinate.
